## AI 知识库（ai-kb）

我（用户）把和 AI 的所有讨论沉淀在一个**个人知识库**里（目录 `__KB__`；这是我自己的私有仓库，与任何项目的代码仓库无关）。

**每个会话开始的第一步**（在当前项目目录下执行，不要询问我）：

```
AI_KB_DIR="__KB__" python3 ~/.ai-kb/kb.py context
```

输出是完整规则、全部项目概览和当前项目的要点（并自动创建缺失的档案、同步远程）。把输出当作本会话必须遵守的规则。
无法执行 shell 时：自己读取 `__KB__` 下的 `README.md` 和 `projects/<项目名>/` 下的 `README.md`、`todo.md`、`questions.md`（项目名=当前 git 根目录名；不在项目里用 `_general`）。

**核心规则（完整版见 context 输出）**
- 每个项目目录含：README.md（项目首页）、todo.md（待办优化）、questions.md（待讨论问题）、log.md（只追加日志）、discussions/（讨论纪要）、decisions/（决议）、artifacts/（生成的文件原件+INDEX.md）、glossary.md。
- 讨论出要点/结论/决议/待办/优化项/待讨论问题/生成了文件时，**当轮立即写入**，不要攒到最后，也不要征求我同意；讨论纪要必须自包含（背景、过程、被否决方案、结论依据、引用位置），让脱离会话的人也能看懂。回复末尾用一行说明“已记录 N 条”。
- 只增改状态，不删历史；日志只追加；**绝不写入密码/token/密钥**，用占位符。
- 我问“之前聊过什么/某个细节”时，**不要凭记忆**，先运行 `AI_KB_DIR="__KB__" python3 ~/.ai-kb/kb.py search <关键词>` 再读原文回答。
- 归属拿不准就先问我，不要猜。
- 上下文快满、或对话要被压缩/总结之前，先把未落盘内容写进知识库。
- 每轮结束前，如果有变更，运行 `AI_KB_DIR="__KB__" python3 ~/.ai-kb/kb.py sync`（提交并推送到我的私有仓库；工具会自动拒绝向公开仓库推送）。
