## AI 知识库规则（精简注入版；完整规则见 {RULES_FULL}，有疑问时再读）

知识库 {KB}（用户私有仓库，与项目代码仓库无关）。每个项目一个目录 `projects/<项目名>/`：README.md（首页，别改 AUTO 区块）、todo.md、questions.md、log.md、glossary.md、discussions/、decisions/、artifacts/(+INDEX.md)。

### 🔋 省上下文（最重要）
- **不要 Read 整个 todo.md / questions.md / log.md / glossary.md**（单个可达几十 KB）。按需用下面的命令或 `grep -n` 取片段。
- 只有用户问到某个项目/历史细节时才去查；当前问题与知识库无关就不要读它。
- 命令（`KBPY` = `python3 {SCRIPT}`）：
  - **`KBPY record <项目> <<'KB' … KB`：一轮要记的所有内容（纪要/决议/待办/问题/勾掉待办/问题结案/产物/日志）放在这一次调用里写完（首选，省 token）**。每条以一行 `@@类型 …` 开头：`@@discussion 主题`（下接正文）、`@@decision 标题 | 一句话结论`（下接正文）、`@@todo …`、`@@q …`、`@@done T-12 说明`、`@@resolve Q-3 结论`、`@@artifact 源路径 | 说明 | 来源纪要`、`@@log 动作 | ID | 说明`。先整体校验，有错一条都不写并列出原因 → 修正后重试；重试仍失败，在回复末尾告诉用户哪些没写进去及原因。
  - `KBPY brief [项目]`：项目简介/当前状态/关键决议 + 最要紧几条（约 3KB）
  - `KBPY search <词>...`：全库搜索，返回 文件:行号
  - `KBPY add-todo <项目> "[类型|优先级] 内容（文件:行号）— 来源"`：自动编号、写入 todo.md 未完成并记 log
  - `KBPY add-q <项目> "[待讨论] 问题 — 来源"`：自动编号写入 questions.md 未决并记 log
  - `KBPY next-id <项目> T|Q|D`：只取下一个编号（编号别手算；新编号带本机前缀如 `T-xing-70`，引用时照抄完整编号）
  - `KBPY log <项目> "动作 | 条目ID | 说明"`：追加日志
  - 改已有条目（勾掉待办、问题转已决议）：先 `grep -n "T-12 " 文件` 定位，再 Edit 那一行。

### 记录（当轮做，不用征求同意）
- 有实质讨论结论/决议/待办/待讨论问题/产物时记录：纪要 `discussions/日期-主题.md`（自包含：背景、事实与代码位置、否决方案及原因、结论、遗留）；决议 `decisions/D-<n>-主题.md` 并在 README 关键决议加一行；产物原文件存 `artifacts/` 并登记 INDEX.md；代码改动只记引用。
- 尽量一次 `record` 调用写完本轮全部记录；下面的单条命令和 Edit 仅用于 record 不覆盖的情况（如修改已有纪要中间段落）。
- 纯问答、小改动、无新结论 → 不记。回复末尾一行「已记录 N 条（T-3…）」，无则不提。
- 用户原话与「（AI 补充）」分开标注；不确定标「（待核实）」；**绝不写入密钥**（用 `<TOKEN>`）。归属拿不准先问用户。

### 🚫 删除红线
任何文件/内容都不许删除、清空、截断或改名丢旧名；过时结论旁边追加修订。唯一例外：用户本轮明确说「删掉 X」。拿不准就留着并问用户。
