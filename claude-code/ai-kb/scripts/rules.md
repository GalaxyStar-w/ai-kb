## AI 知识库规则（由 ai-kb 工具注入，请严格遵守）

用户把和 AI 的所有讨论沉淀成一个**个人知识库**（{KB}，是用户自己的私有仓库，与任何项目的代码仓库无关）。目标：用户**脱离会话**后，只凭这些文档就能找到并**完全理解**此前讨论、生成的一切；需要某个项目的细节时，能找到最详细的内容。所以记录要**详细、自包含、可追溯**，不能只记一句话。

### 目录结构（每个项目一个目录 `projects/<项目名>/`；不在具体项目下的讨论用 `_general`）
| 文件/目录 | 作用 | 谁维护 |
|---|---|---|
| `README.md` | 项目首页：简介、背景、当前状态、关键决议；底部“自动区块”是脚本生成的导航 | AI 维护正文，**别改自动区块** |
| `todo.md` | 待办与优化清单（未完成/已完成） | AI |
| `questions.md` | 待讨论问题（未决/已决议） | AI |
| `log.md` | 只追加的时间线日志 | AI 追加 |
| `discussions/YYYY-MM-DD-<主题>.md` | 讨论纪要（详细、自包含） | AI |
| `decisions/D-<n>-<主题>.md` | 重要决议记录 | AI |
| `artifacts/` + `artifacts/INDEX.md` | 讨论中生成的文件原件 + 索引 | AI |
| `glossary.md` | 术语、缩写、系统/表名含义、人物角色 | AI |
根目录 `README.md` 是**脚本自动生成的总页**（所有项目汇总），不要手改。

### 必须当轮记录（不需要用户提醒，也不征求同意；不要攒到最后）
1. **讨论纪要**：每个讨论主题每天一个文件 `discussions/日期-主题.md`，随讨论进行**逐轮补充**。必须自包含，含：背景与目标、关键事实/数据/代码位置（文件:行号、表名、链接、commit）、讨论过程要点、**考虑过但被否决的方案及原因**、结论、遗留问题、产出物链接。写到“一个没参与讨论的人也能看懂”。
2. **决议**：做出重要决定时写 `decisions/D-<n>-<主题>.md`（背景、可选方案、结论、原因、影响、来源讨论），并在项目 README 的“关键决议”加一行。
3. **待办/优化项**：写入 `todo.md` 的“未完成”，格式 `- [ ] T-<n> [类型|优先级] 内容（文件:行号）— 来源 · 提出日期`，编号=现有最大+1；完成后移到“已完成”并写完成日期，**不删除**。
4. **待讨论问题**：用户提出但没讨论完、或需要用户拍板的，写入 `questions.md` 的“未决”（`- Q-<n> [待讨论|讨论中] 问题 — 提出日期 · 最近触及日期 · 来源`）；有结论后移到“已决议”并写 `→ D-<n>`。
5. **产物**：讨论中生成的独立内容（文档、报告、脚本、SQL、配置、图表等）把**原文件存入 `artifacts/`**（文件名带日期），并在 `artifacts/INDEX.md` 登记（用途、日期、来源讨论）。对项目仓库里已有的代码改动，只记录引用（文件路径+说明，有 commit 则记 hash），不要复制。
6. **术语/背景**：出现项目专有名词、缩写、系统/表含义，补进 `glossary.md`。
7. **日志**：每次写入以上任何内容，在 `log.md` 追加一行 `- 日期 | 动作 | 条目ID | 说明`。
8. 回复末尾用一行说明“已记录 N 条（T-3、Q-2、D-1 等）”；本轮确实没有可记录内容就不提。

### 规范
- **忠实记录，区分来源**：用户明确说的事实/理由/结论，照实记录；你（AI）补充的分析、推测、常识性理由，必须标注“（AI 补充）”，不能写得像用户说过的；不确定的信息标“（待核实）”。这样用户日后能分清哪些是当时的决定、哪些只是 AI 的意见。
- **绝不写入**密码、token、API key、私钥、连接串里的账号密码等凭证，用占位符 `<TOKEN>` 代替。工具会在提交前扫描并拦截疑似密钥。
- 只增改状态，不删除历史；日志只追加。
- 主题归属：同一对话内的延续归入当前主题；新对话内容明显属于已有主题就归入，明显是新主题就新建，**拿不准先问用户，不要猜**。
- 对话压缩前，必须保证未落盘内容已写入。

### 查询（用户问“之前聊过什么/某个细节”时）
- **不要凭记忆回答**。先读当前项目 README 与相关文件；找不到就运行“当前位置”里给出的**搜索命令**（或直接在知识库目录里全文搜索），再读命中的讨论纪要/决议原文，据此回答并给出文件路径。
- 用户说“看下清单/还有什么没做”：汇总 todo.md 与 questions.md 的未完成项，按优先级排序，不要整篇转储。

### 新会话开场
- 若当前项目有待讨论/讨论中的问题，用一两句话列出最久没触及的 2-3 个，问用户是否接着聊（不要打断用户已提出的具体请求）。
- 若“同步警告”里有内容，先简短告知用户。
