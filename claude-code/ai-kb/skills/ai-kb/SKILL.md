# ai-kb 使用说明

知识库由 hook 自动维护：会话开始注入规则和当前项目要点，每轮提醒记录，压缩前保护，回合结束检查并提交、后台推送。规则全文由 SessionStart 注入（以注入内容为准）。本 skill 只处理**用户主动发起**的操作。

## 知识库长什么样

目录 = `AI_KB_DIR`，默认 `~/ai-knowledge-base`（SessionStart 注入里有实际路径与搜索命令）。

```
README.md                      总页（脚本自动生成，勿手改）：所有项目汇总、全部待办/问题、最近更新
projects/<项目>/README.md      项目首页（简介/状态/关键决议 + 脚本生成的档案导航）
projects/<项目>/todo.md        待办与优化清单
projects/<项目>/questions.md   待讨论问题
projects/<项目>/log.md         只追加日志
projects/<项目>/discussions/   讨论纪要（自包含）
projects/<项目>/decisions/     决议记录
projects/<项目>/artifacts/     生成的文件原件 + INDEX.md
projects/<项目>/glossary.md    术语与背景
_meta/                         映射、配置、同步状态
```

## 常见操作

**问"之前聊过什么 / 某个细节"**：**不要凭记忆答**。先读该项目 README；不够就用注入里给的搜索命令（`kb.py search <词>`）定位，再读命中的讨论纪要/决议/产物原文，据此回答并给出文件路径。信息缺失就明说缺失，不要编造。

**看清单 / 还有什么没做**：汇总该项目（或全部项目）todo.md 的"未完成"与 questions.md 的"未决"，按优先级和最久未触及排序；不要整篇转储。

**看总页 / 所有项目**：读根目录 `README.md`；需要刷新时运行 `kb.py build`。

**追溯**：`log.md` 看时间线；`git -C <知识库> log -p -- <文件>` 看某文件的变更历史。

**整理 / 归档**：把全部完成的待办保持在"已完成"；过长的讨论纪要补一个"摘要"小节放在文件开头；检查 README"当前状态/关键决议"是否过时并更新；检查 artifacts/INDEX.md 是否登记齐全；运行 `kb.py build`；最后给用户变更摘要。

**审计漏记**：用会话历史检索找该项目近 7 天的会话，对照知识库，找出"讨论过但没记录"的内容，只读报告到 `_audit/<日期>.md`，由用户确认后再补录。

**同步**：运行 `kb.py sync`（构建总页 → 密钥扫描 → 提交 → 拉取 → 推送）。推送前工具会检查远程 GitHub 仓库是否**私有**，公开仓库一律拒绝；提交前会扫描疑似密钥，命中则拦截并写 `_meta/SYNC_BLOCKED.md`。遇到这两种情况，把原因告诉用户并给出处理办法，**不要绕过**。

**换电脑 / 恢复**：新机器安装插件后，`git clone <私有仓库> ~/ai-knowledge-base`（或设置 `AI_KB_DIR`），新会话开始时 hook 会自动加载并拉取。

## 排障

- 没自动记录：先查是否授权了写入知识库目录（`permissions.additionalDirectories`，目录要在会话启动前存在）、`python3` 是否可用。
- 推送失败：`kb.py status` 看同步状态；常见原因：仓库公开（被拒）、账号无写权限、需要登录 `gh auth login`、网络。
- 不要替用户修改仓库可见性、登录账号或 settings，除非用户明确要求。

## 注意

- 知识库可能含公司相关信息：只放用户自己的私有仓库，不要上传到其他地方，不要在回复里无关地大段引用。
- 绝不写入凭证；发现凭证用占位符替换。
