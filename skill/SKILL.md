# ai-kb · 讨论持久化知识库

把和用户的每次讨论自动变成可检索、可追溯、跨机器的文档。

## 什么时候用

| 用户说| 做什么 |
|---|---|
| 「之前我们聊过 XX 怎么办」 | **先 `search`**，再读原文回答，不要凭记忆 |
| 「把这次讨论记下来」 | 当轮写入对应文件（见下方「每轮该做什么」） |
| 「装一下知识库工具」 | 见下方「首次安装」 |
| 讨论出结论/决议/待办 | **当轮就写**，不攒到最后、不征求同意 |

---

## 首次安装（如果 `~/.ai-kb/kb.py` 不存在）

```bash
git clone https://github.com/GalaxyStar-w/ai-kb.git ~/ai-kb-tool-repo
bash ~/ai-kb-tool-repo/bootstrap.sh
```

脚本会自动：体检依赖 → 创建知识库骨架 → 装工具 → 配 hook → 自测。

**装完提醒用户两件事**：
1. 重启 agent（WorkBuddy 用 **Cmd+Q 彻底退出**，关窗口不算 —— 它有常驻进程）
2. 之后说「按 `~/ai-knowledge-base/AI-START-HERE.md` 走」

---

## 三条命令（核心）

```bash
KB=~/ai-knowledge-base   # 换成实际路径

AI_KB_DIR=$KB python3 ~/.ai-kb/kb.py context      # 加载规则 + 概览 + 现在该管什么
AI_KB_DIR=$KB python3 ~/.ai-kb/kb.py search <词>   # 搜历史讨论，返回 文件:行号:内容
AI_KB_DIR=$KB python3 ~/.ai-kb/kb.py sync         # 提交 + 推送
```

**更多命令**：`build` / `status` / **`doctor`（体检）** / **`audit`（盘点）** / `init` / `clean-stale` / `export`

## 🔴 四条硬性规则

### 1. 删除红线 —— 任何内容都不许删

用户明确要求「所有内容全部不允许删除」。

- ❌ 不许删任何文件（**包括看起来是垃圾的**：空壳项目、临时目录、测试残留、中间产物）
- ❌ 不许清空或截断 —— 判断「结论过时」也只能**追加**「原结论已修订」，不能抹原文
- ❌ 不许改名导致旧名消失
- ❌ 不许用「归档」「整理」「规范化」当借口删东西
- **唯一例外**：用户在本轮对话里明确说「删掉 X」

**判断不确定 → 留着，然后问用户。宁可冗余，也不要丢任何一条历史。**

> 真实案例：一份实战纪要曾被当「测试残留」删除，事后才从 git 历史恢复。

### 2. 改用户已有的文件前必须问

流程：**先提案 → 等点头 → 改前备份 → 动手 → 改后汇报**（改了什么、备份在哪、怎么回滚）

### 3. 只认实测，不认记忆

涉及凭证、可见性、配置的事实，动手前先实测（`gh` / `ls` / `curl`）。
**不要用「配置里没有某项」推断「平台不支持某项」** —— 那是「没配过」，不是「不支持」。

### 4. 绝不写凭证

密码 / token / API key / 私钥 → 一律用占位符（`<TOKEN>` / `<KEY>`）。

## 知识库结构

```
<KB>/
├── README.md              自动生成的总页（所有项目汇总 + 待办导航）
├── AI-START-HERE.md      给 AI 的总入口
├── _meta/                 安装说明、机器配置、路径映射
├── _tool/                 工具源码
└── projects/<项目名>/
    ├── README.md          项目首页
    ├── todo.md            待办与优化清单
    ├── questions.md       待讨论问题
    ├── log.md             只追加的日志
    ├── glossary.md        术语表
    ├── discussions/       讨论纪要（自包含）
    ├── decisions/         决议
    └── artifacts/         产物原件 + INDEX.md
```

**项目归属**：项目名 = 当前工作目录的 git 根目录名；不在任何项目里 → `_general`。拿不准先问用户。

## 每轮该做什么

**讨论出以下任何一项，当轮就写**，不攒到最后、不征求同意：

| 类型 | 写到哪 |
|---|---|
| 讨论要点 / 过程 / 结论 | `discussions/YYYY-MM-DD-<主题>.md` |
| 决策、约定、原则 | `decisions/D-n-<标题>.md` |
| 待办、优化项、缺陷 | `todo.md`，格式：`- [ ] T-n [类型\|优先级] 内容（文件:行号）— 来源 · 日期` |
| 待讨论的问题 | `questions.md` |
| 生成了文件 | `artifacts/` 存原文件 + 登记 `artifacts/INDEX.md` |
| 任何一行变更 | `log.md` 追加一行（只追加） |

**讨论纪要必须自包含** —— 写到「一个没参与讨论的人也能看懂」：
背景与目标 · 关键事实（文件:行号 / 表名 / commit）· 讨论过程要点 ·
**考虑过但被否决的方案及原因** · 结论 · 遗留问题 · 产出物链接。

**区分来源**：用户说的照实记；你补充的标「（AI 补充）」；不确定的标「（待核实）」。

**回复末尾标注「已记录 N 条」**。

## 回答历史问题的标准流程

```
用户：「之前聊过 XX 怎么办？」

❌ 凭记忆回答
✅ ① kb.py search XX
   ② 读命中的原文文件
   ③ 基于原文回答，注明出处（文件路径）
```

## 安全（工具自带，不要绕过）

| 保险 | 作用 |
|---|---|
| 只推私有仓库 | 远程是 PUBLIC 就拒绝推送 |
| 提交前密钥扫描 | 发现真 key 整批拦住，写出 `_meta/SYNC_BLOCKED.md` |
| **不提供任何删除命令** | 10 个命令没有一个能删文件 —— 物理删除只能手工操作 |
